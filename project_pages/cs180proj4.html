Part 1: Fit a Neural Field to a 2D Image

My MLP was implemented with a class, and a forwarding function. The MLP is initialized with attributes where width/hidden_dim = 256; a learning rate of 1e-4 as given in the project spec; a max frequency level = 10; and 4 connected layers. I sequentially pass the positional encoding value through the linear layers, and non-linear activations (ReLU), and I end it off with a Sigmoid operation.

For my forwarding function, I run the 2D pixel coordinates through my positional encoding function to give them more dimension. I then run these coordinates through the model, and return the predicted RGB pixels.

Part 2: Fit a Neural Radiance Field from Multi-view Images

Part 2.1: Create Rays from Cameras

For this part of the project, I implemented 3 functions, who's overall goal was to be able to create a ray for each pixel. Ray's are a vector/straight line that extends between our virtual camera's position, to the 3d scene it's photographing. Referencing our camera cloud from part 0, each image in the cloud is our 'virual camera'; in the center of the cloud is our 3d object; and rays would be straight lines connecting each pixel our camera's capture to what part of the 3d scene our pixel is showing.

The functions were: transform(), pixel_to_camera(), and pixel_to_ray()

Implementing them was pretty straightforward. I just used some numpy linear algebra operations for each of them. The transform(), and pixel_to_camera() functions were helpers used to make pixel_to_ray().

Part 2.2: Sampling & Part 2.3: Putting the Dataloading All Together

I've combined both of these parts into 1 paragraph section because I ended up putting the sampling-rays-from-images function from 2.2 into the dataloading class in part 2.3. This descision was made because the dataloader written in the viser code in the spec calls a sample_rays() function that presumably does the same job as the 2.2 sampling-rays-from-images function. I didn't want to change the viser code too much.

Let's start describing the implementation with the dataloader, which converts randomly sampled pixels from multiview images into rays. The dataloader was implemented using a RaysData class that stores: list of the images; K, the intrinsic matrix; the c2w matricies for each image; a list of flattened pixels across all the images; the height/width of the images; the total pixel count; the coordinates of each pixel in the images list; and the coordinate rays and directional rays for each pixel.

When the the dataloader is initalized, the pixel coordinates and rays are automatically initialized. The rays are calculated using the pixel_to_ray() function from part 2.1.

The sampling-rays-from-images function detailed in part 2.2 is the sample_random_rays() function, apart of the RaysData class. This function is simple, randomly indexing the pre-computed rays in the class object. Originally, this function wasn't going to be apart of the class, and would compute rays on the fly. However, because the viser code had rays_o and rays_d as RaysData class attributes, meaning that I would need to pre-compute all the rays anyways, there was no point to make the sampling rays function external.

The 2.2 function for sampling random ray points, my sample_points_along_rays() function, is outside of the RaysData class. It takes each ray and turns it into a set of 3D sample points. It does this by choosing evenly spaced depth values between a near and far range, then optionally adding a bit of random noise so the samples aren’t always in the exact same spots.

Part 2.4: Neural Radiance Field

I implemented my NeRF model using a class, and forwarding function. I broke down the network's structure into the following: The first chain of linear operations before the coordinate positional encoding is concatenated; The second chain of linear operations after coord PE concatination; a density branch (that returns the pixel density values); and a color branch (that returns pixel RGB values) that gets concatenated half way through. I defined each of the output of each linear operations for each section of the network structure in the model's initialization. Then in my forwarding function, I connect all of these linear operations in 1 chain.

Part 2.6: Training with Your Own Data

My data was 44 pictures of my tonkotsu ramen bowl.

Hyperparameter Changes:

near value: 2.0 to 0.02
far value: 6.0 to 0.5
number of iterations: 1,500 to 10,000
I didn't have as many pictures, nor as pictures of as-good quality as the lego excavator ones. I had to run more iterations to train the model on the worser data.
batch_size (number of rays randomly sampled): 10,000 to 1,000
When I tried keeping the larger batch size, CoLab started freaking out about GPU usage.

Other Changes:
